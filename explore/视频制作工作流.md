# Mercury 视频制作工作流与仓库改造

你交一份文稿，我先和你定下观众看完能回答的一个问题。随后你依次审阅**优化稿、静音动态分镜、带本人音色的全长预演**。画面获批后才生成口播，终审通过后才导出完整视频。前期用台词定位动作，后期用真实读音、停顿和重音确定帧数。[制作需求](../requirements.md)

## 一份文稿如何走到成片

| 阶段 | 我交给你什么 | 通过后发生什么 |
| --- | --- | --- |
| 1．优化文稿 | 保留原稿，另交一版可直接朗读的稿。沿用你的观点、经历和说话习惯，删重复、拆长句。开头明确观众想弄清什么；需要证据的数字、实验或经历旁边标明出处或待补项。 | **你审文稿**，确认事实、语气和取舍。给定稿的段落分配稳定编号。 |
| 2．设计分镜、构图、运镜 | 按意思分段，为每段交起止关键帧、台词锚点、素材缩略图和构图说明。把段落串成静音动态分镜，用字幕代读；最难解释的变化用简单图形先跑一遍。此时标的秒数都是估算。 | **你审画面**，能指出哪句该配哪张图、该在哪里推近、哪里需要停留。批准这版分镜后才进入音色合成。 |
| 3．用你的音色配音 | 用你提供的参考录音，先取含专名、转折和停顿的一小段试读，确定声线与语速后分段合成。保存干声 WAV；按已审稿核字，用实际录音定时，校正数字、读音和字幕起止，生成干净 SRT。以同一事件表重排视觉入点和拟音，加入背景音并压低人声下方的音乐。 | 交**完整口播、字幕和全长低清带声预演**，你可以连续听，也可以按镜号定位。缺少本人参考录音时，项目停在已审分镜，可直接从配音续做。 |
| 4．终审与成片 | 你按镜号或时间指出读音、节奏、构图或混音问题，我改受影响的段落并交回预演。**你确认最终预演版本后**，用该版时间线、素材和分轨渲染全片。 | 交 MP4、SRT、旁白和可重渲工程。一倍速看相邻镜头是否连贯，手机尺寸读截图，试听旁白是否清楚，再核对导出时长和音轨。 |

**返修如何生效。** 改读音只重生成相应段落的人声，重算该处及后续偏移；换截图只重做相关镜头。改动论点或台词含义，要回到相应稿段和分镜重新确认。每次审阅都记录稿件、分镜或预演的版本和意见，最终渲染读取最后确认的组合。

## 怎样从一句话构造连续镜头

先圈出这段让观众理解的**一个变化**。把台词中的动词还原为对象、动作和结果。每个镜头记下对应稿段、触发词、起始构图、视线落点、对象如何进出、镜头怎样移动、结束时交给下段什么。多句解释同一个动作时可以共用一镜。真实网页负责证明“确实如此”，截图保留标题和关键上下文；代码动画负责展示网页看不到的过程。

例如文稿说“代理接过了服务器的一部分工作”。先让观众看见服务器旁堆着哪些任务；说到“接过”时，把其中一项移向代理，视线跟着它走；说到余下负担时拉回全景，服务器和代理仍在原位。初审时你就能判断有没有讲清楚**谁接了哪项工作**。配音后只需把交接帧移到你念“接过”的位置。[网关案例的镜头分析](Nginx网关视频.md)

| 你的四类话题 | 分镜围绕什么展开 | 证据和节奏如何选 |
| --- | --- | --- |
| 常识科普，如现金怎样产生 | 跟一笔钱从一个角色流到另一个角色，保持金额、对象和箭头可追踪。 | 在最易误解的一步插入权威原文或实物；给观众时间把示意与证据对上。 |
| 观点讨论，如 AI 为什么只能提效 | 用同一件工作呈现原流程、采用 AI 后的变化和仍需人决定的一步，留出反例。 | 用实际产物或录屏支撑判断；区分观察和个人结论，让观众看到观点成立的条件。 |
| 技术科普，如 Agent 沙箱或高并发 | 跟一个请求、文件或状态走，先复现困难，再引入组件。 | 用可复核的输入、日志和结果钉住因果；空间位置保持一致，只在需要看细节时推近。 |
| 个人生活，如工作期间读书 | 围绕一次具体选择组织场景、犹豫、行动和后果，留住一件可辨认的道具。 | 优先用你的照片、日历或录音；重要处给停顿。补画的场景标为示意。 |

## 五份参考分别用在什么地方

构造分镜、配声或返修时，从[剪辑技巧索引](index.md)按当前问题选 skill 或作品。下表用于回顾每个来源的研究笔记。

| 遇到的制作问题 | 取用的方法 |
| --- | --- |
| 参考片好看，但换个题目就不知道怎么用 | 找到可回看的原例，写出动作、适用条件和验收问题，拿本期文稿试一次，在本片的 `skills/` 留下方法与适用条件。[仓颉 · 提取可复用方法](仓颉技能提炼.md) |
| 技术名词多，讲到一半观众丢了主线 | 固定一个可追踪对象；旧方案遇到可见困难时引入下一层，最后回到开场的同一张图。[Nginx · 用一条请求串起全片](Nginx网关视频.md) |
| 文稿通过了，执行者仍不知道要画什么 | 在台词旁写下起始状态、动作、视线落点和交给下镜的状态，用代表段核对方向和节奏。[Table-video · 把口播写成镜头剧本](Table-video镜头剧本.md) |
| 每镜都做了，连起来却像幻灯片 | 导演先排整段的铺垫与揭示，用几何草图跑通关键变化，最后按事件帧配音效、随旁白试听。[Vibe Motion · 代码动作与声音](Vibe-Motion制作经验.md) |
| 作者说“这里太快”，返修时找不到那一拍 | 用镜号、预演版本、台词或秒点标记同一区域，修后带上前后镜头一起回看。[OpenFilm · 定位与审片](OpenFilm审片.md) |

## 怎样判断成片符合需求

- **主线和参考风格。** 为本期选一段最接近的参考，记录要借的是空间关系、揭示的时机还是情绪。分镜初审时并排看参考和本片代表段。静音连看两镜，观众应能跟住同一人物、物件或请求，并指出这次运动多解释了什么。需要读证据或等人物反应时，允许镜头停稳。
- **网页证据与视觉资产。** 要证明某项功能、数据或实验结果时，从真实页面或本地演示取原图，记录页面名、来源、日期和它支持的那句台词。先给上下文，再推近目标，按实际语速留出阅读时间。新找到或生成的 Logo、插画和引用截图收进 `projects/<片名>/assets/`，项目记录素材路径、来源或生成提示词、采用版本。生成图用于示意；网页引文回到原截图核查。
- **声音和导出。** 单听旁白核对专名、断句和重音，再合听音乐与拟音；重要字被盖住时，先让伴奏在该句退下。终审按实际画幅看全长预演，重点检查入出镜、字幕遮挡和截图可读性。导出后用 ffprobe 核对音画时长与轨道，再抽查关键动作和片尾，和终审版对照。

## Skill、Agent 和工具如何分工

| 决定 | 使用方式 |
| --- | --- |
| 自建一个 Mercury 导演 skill | 负责接稿、三次审阅、选定版本和恢复进度。导演由 Astra（gpt-6.2-astra）处理需要判断的稿件结构、分镜和跨段节奏。题意与镜头都清楚时，由 Sol（gpt-6.2-sol）直接执行。 |
| 融合已有分镜方法 | 文稿阶段借用 table-video 的镜头剧本和相邻状态；机制图借用 remotion-code-motion-explainer 的可见因果；生成旁白后用 direct-narrated-motion 的 SRT 锚点、素材标注和跨句动作。全程维护同一套镜号。auto-motion 可借用语义拆段和单镜重渲的做法。[分镜技巧与对应 skill](index.md#叙事与分镜) |
| 复用声音技能，单独接入语音合成 | Sol 调用支持中文参考音色的 TTS 后端生成旁白。具体后端待本人音色试读后选定，用同一句比较读音、停顿、相似度与能否局部重录。现成拟音、程序音、混音分别交给 sfx-sources、procedural-audio、audio-mixing。[声音技巧与对应 skill](index.md#配音节奏与声音) |
| 执行和复核按需分派 | 素材与实现 Agent 用 Sol，负责整理出处、做截图标注、写 React / Remotion 镜头及 FFmpeg 混音。长片按连续段落分派，各人拿同一版素材、镜号和边界状态。审片 Agent 用 Sol 检查字幕、尺寸、衔接和导出；难判断的叙事问题交导演及作者。Python 做转写和批处理，ffprobe 核轨道。 |
| 有新参考时再提取 skill | 用仓颉把“时码、作者讲了什么、画面如何印证、适用条件”写成方法卡。方法卡写入本片的 `skills/`，据此调整的镜头模板写入本片的 `src/`。OpenFilm 可用于需要时间线批注的项目。[资料入口](../reference/reference.md) |

## 项目结构与上下文

**一部片对应一个项目目录和一个独立会话。** 在 Mercury 根目录的新对话直接贴稿即建片，后续在同一对话以返回的 `projects/<片名>/` 为单片工作目录。导演读取本片的文稿、项目记录和这次选用的公共资源。返修原片时回到原项目；另起一部片时，从新文稿和公共基线开始。搜索素材、检索技能、恢复进度时都指定当前项目，避免遍历同级项目。给子 Agent 的任务也只附本片所需的文件和已选公共资源。

| 职责 | 仓库公共层 | 单片目录 `projects/<片名>/` 内 |
| --- | --- | --- |
| 代码 | `src/` 放共享组件、音频对齐、预演和导出程序 | `src/` 放本片镜头、时间线、特效和一次性 Python / Node.js 工具。可调用公共代码；片内改版写在本片。 |
| 素材与参考 | `assets/` 供应已批准共享的素材，`reference/` 放公共研究资料 | `assets/` 收本次找到或生成的截图、Logo、插画、音效等。`reference/` 收本片新增的参考视频、转写和时码。改用公共素材时，派生版本也落在本片。 |
| 技能与配置 | `.codex/` 管理公共导演 skill、prompt、子 Agent 配置和插件 | `skills/<方法名>/SKILL.md` 放本片的提示、参考拆解和返修经验，本片导演按路径读取，其他项目的发现入口只包含各自的技能。 |
| 制作输入与输出 | 公共制作命令按指定项目运行 | `manuscript/` 放原稿、优化稿与定稿；`storyboard/` 放分镜及台词锚点；`audio/` 放干声、字幕和分轨；`review/` 放预演与审阅意见；`exports/` 放获批版本的交付文件。 |
| 进度与版本 | 公共工作流定义审阅顺序 | `project.json` 记录本片当前阶段、采用的稿件、分镜、音轨、素材版本和终审结果。恢复进度时直接打开这份文件。 |

**渲染是代码执行的动作。** 例如公共 `src/render.ts` 可以接收项目路径，加载本片的 `src/` 和已选时间线。静音或带声预演写到本片 `review/`，终审后的 MP4、SRT 写到本片 `exports/`。原先含义容易混淆的 `script/` 用 `manuscript/` 表示文稿，可执行脚本则按归属放进相应的 `src/`。项目初始化、[静音及带声预演](../src/film-media.md)、[本人音色配音与字幕](../src/film-voice.md)、[交审、返修与获批版本导出](../src/film-review.md) 均接受明确的单片路径。端到端制作还需本期的镜头实现、审阅结论和音色素材。

**制作中调整。** 假如审完第 4 镜，你要求用仓颉逆向一段新的参考视频：原片和时码进本片 `reference/`，提炼的镜头规则进本片 `skills/`，改过的构图与实现分别进本片 `storyboard/` 和 `src/`。重新预演，在本片 `review/` 记录意见和采用版。公共层在这次制作中作为只读依赖，项目事实、个人音色、偏好和试验结论都留在本片。

**交付与沉淀是两次独立决定。** 终审通过，导出并记录采用版本，项目即可结束。等你明确要求整理这一期，再从你点名的项目整理候选项，列出本地来源、拟共享的内容、依赖和目标位置。由你选择范围后，技能进入公共 `.codex/skills/`，素材进入公共 `assets/`，代码进入公共 `src/`。公共 skill 可以直接引用根目录 `reference/` 的原件。公共调研阶段的经验先留在 `explore/` 供你 Review，你选定哪些就整理哪些。保留原片采用的版本和素材，使已交付项目仍可重渲。

公共配置按用途维护：`.codex/prompts/` 放通用交接模板，`.codex/agents/` 放可选的制作和审片角色，主会话担任导演，`.codex/plugins/` 放拟分发的公共插件。公共导演从当前项目记录取得输入和审阅状态。

实施仓库改造时，先让公共导演和制作入口接受明确的项目路径，再用两份独立文稿检查隔离：在 A 片修改镜头、素材和 skill 后，新开的 B 片应仅加载 B 的内容与公共基线，重新打开 A 片应能恢复 A 的最后审阅版本。
