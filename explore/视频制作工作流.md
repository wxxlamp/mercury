# Mercury 视频制作工作流与仓库改造

你交一份文稿，我交回三个可审的版本：**能念的稿、能看的静音分镜、能听的带声预演**。你审定带声预演后，再生成完整视频。分镜在配音前确定叙事和画面，用台词定位动作；配音后用你的实际发音、停顿和重音确定帧数。

## 一份文稿如何走到成片

| 阶段 | 我交给你什么 | 通过后发生什么 |
| --- | --- | --- |
| 1．优化文稿 | 保留原稿，另交一版可直接朗读的稿。沿用你的观点、经历和说话习惯，删重复、拆长句。开头明确观众想弄清什么；需要证据的数字、实验或经历旁边标明出处或待补项。 | **你审文稿**，确认事实、语气和取舍。给定稿的段落分配稳定编号。 |
| 2．设计分镜、构图、运镜 | 按意思分段，为每段交起止关键帧、台词锚点、素材缩略图和构图说明。把段落串成静音动态分镜，用字幕代读；最难解释的变化用简单图形先跑一遍。此时标的秒数都是估算。 | **你审画面**，能指出哪句该配哪张图、该在哪里推近、哪里需要停留。批准这版分镜后才进入音色合成。 |
| 3．用你的音色配音 | 用你提供的参考录音，先取含专名、转折和停顿的一小段试读，确定声线与语速后分段合成。保存干声 WAV；用实际录音对齐原稿，校正数字、读音和字幕起止，生成干净 SRT。以同一事件表重排视觉入点和拟音，加入背景音并压低人声下方的音乐。 | 交**完整口播、字幕和全长低清带声预演**，你可以连续听，也可以按镜号定位。缺少本人参考录音时，项目停在已审分镜，可直接从配音续做。 |
| 4．终审与成片 | 你按镜号或时间指出读音、节奏、构图或混音问题，我改受影响的段落并交回预演。**你确认最终预演版本后**，用该版时间线、素材和分轨渲染全片。 | 交 MP4、SRT、旁白和可重渲工程。一倍速看相邻镜头是否连贯，手机尺寸读截图，试听旁白是否清楚，再核对导出时长和音轨。 |

**返修如何生效。** 改读音只重生成相应段落的人声，重算该处及后续偏移；换截图只重做相关镜头。改动论点或台词含义，要回到相应稿段和分镜重新确认。每次审阅都记录稿件、分镜或预演的版本和意见，最终渲染读取最后确认的组合。

## 怎样从一句话构造连续镜头

先圈出这段让观众理解的**一个变化**。把台词中的动词还原为对象、动作和结果。每个镜头记下对应稿段、触发词、起始构图、视线落点、对象如何进出、镜头怎样移动、结束时交给下段什么。多句解释同一个动作时可以共用一镜。真实网页负责证明“确实如此”，截图保留标题和关键上下文；代码动画负责展示网页看不到的过程。

例如文稿说“代理接过了服务器的一部分工作”。先让观众看见服务器旁堆着哪些任务；说到“接过”时，把其中一项移向代理，视线跟着它走；说到余下负担时拉回全景，服务器和代理仍在原位。初审时你就能判断有没有讲清楚**谁接了哪项工作**。配音后只需把交接帧移到你念“接过”的位置。[网关原片与镜头对照](../reference/sources/README.md#小盒子童鞋--同一条请求如何贯穿多个概念)

| 你的四类话题 | 分镜围绕什么展开 | 证据和节奏如何选 |
| --- | --- | --- |
| 常识科普，如现金怎样产生 | 跟一笔钱从一个角色流到另一个角色，保持金额、对象和箭头可追踪。 | 在最易误解的一步插入权威原文或实物；给观众时间把示意与证据对上。 |
| 观点讨论，如 AI 为什么只能提效 | 用同一件工作呈现原流程、采用 AI 后的变化和仍需人决定的一步，留出反例。 | 用实际产物或录屏支撑判断；区分观察和个人结论，让观众看到观点成立的条件。 |
| 技术科普，如 Agent 沙箱或高并发 | 跟一个请求、文件或状态走，先复现困难，再引入组件。 | 用可复核的输入、日志和结果钉住因果；空间位置保持一致，只在需要看细节时推近。 |
| 个人生活，如工作期间读书 | 围绕一次具体选择组织场景、犹豫、行动和后果，留住一件可辨认的道具。 | 优先用你的照片、日历或录音；重要处给停顿。补画的场景标为示意。 |

## 从猫学长口述中保留的决定

- **先让一个动作成立。** 第 01 集把指尖轨迹画回原视频验证，第 04 集先用圆锥看鱼群运动。分镜初审先交能判断对错的运动草图。外观再精细也很难帮观众读懂错误的轨迹。[第 01 集 00:59 起](../reference/vibe-motion/series/transcripts/01.txt) · [第 04 集 00:47 起](../reference/vibe-motion/series/transcripts/04.txt)
- **导演看段落，执行者做镜头。** 第 06 集的主从系统能按 SRT 产出各镜，作者依然觉得成片像 PPT，还要设计铺垫、发展和高潮。第 15 集把“建立预期，再制造反差”的做法从信息论迁移到蝴蝶效应。导演要在静音预演时说清观众在哪一拍开始好奇、何时得到答案。[第 06 集 01:07 起](../reference/vibe-motion/series/transcripts/06.txt) · [第 15 集 00:45 起](../reference/vibe-motion/series/transcripts/15.txt)
- **把复用成本花在第一次。** 第 03、10 集从已有源码起步，替换台词或图形验证镜头能否迁移。入库时把预览、源码、可换参数放一起。按第 07 集的办法，在同一模型和同一段稿上比较加载某个 skill 前后的效果，确有改善才保留。[第 03 集](../reference/vibe-motion/series/transcripts/03.txt) · [第 10 集](../reference/vibe-motion/series/transcripts/10.txt) · [第 07 集](../reference/vibe-motion/series/transcripts/07.txt)
- **声音有两种不同的判断。** 第 13 集从动画代码读出卡片弹出的帧来对齐拟音，又用同一段 7 秒动画盲听两套选声。真实手电筒开关即使评价高，也可能不如专门的 UI 声适合画面。让程序对时，让人连着口播判断材质和轻重。[第 13 集 00:40、02:40 起](../reference/vibe-motion/series/transcripts/13.txt)

## Skill、Agent 和工具如何分工

| 决定 | 使用方式 |
| --- | --- |
| 自建一个 Mercury 导演 skill | 负责接稿、三次审阅、选定版本和恢复进度。导演由 Astra（gpt-6.2-astra）处理需要判断的稿件结构、分镜和跨段节奏。题意与镜头都清楚时，由 Sol（gpt-6.2-sol）直接执行。 |
| 融合已有分镜方法 | 文稿阶段借用 table-video 的镜头剧本和相邻状态；机制图借用 remotion-code-motion-explainer 的可见因果；生成旁白后用 direct-narrated-motion 的 SRT 锚点、素材标注和跨句动作。全程维护同一套镜号。auto-motion 可借用语义拆段和单镜重渲的做法。[镜头剧本](../reference/sources/Table-VideoSOP/skills/table-video/assets/templates/镜头剧本.template.md) · [Vibe Motion 技能目录](../reference/vibe-motion/github/目录.md) |
| 复用声音技能，单独接入语音合成 | Sol 调用支持中文参考音色的 TTS 后端生成旁白。具体后端待本人音色试读后选定，用同一句比较读音、停顿、相似度与能否局部重录。现成拟音、程序音、混音分别交给 sfx-sources、procedural-audio、audio-mixing。[声音完整版](../reference/vibe-motion/github/sound/README.md) |
| 执行和复核按需分派 | 素材与实现 Agent 用 Sol，负责整理出处、做截图标注、写 React / Remotion 镜头及 FFmpeg 混音。长片按连续段落分派，各人拿同一版素材、镜号和边界状态。审片 Agent 用 Sol 检查字幕、尺寸、衔接和导出；难判断的叙事问题交导演及作者。Python 做转写和批处理，ffprobe 核轨道。 |
| 有新参考时再提取 skill | 用仓颉把“时码、作者讲了什么、画面如何印证、适用条件”写成方法卡。在另一类题材的短预演上验证后，再加入导演的资源或可改参数的镜头模板。OpenFilm 可用于需要时间线批注的项目。[资料入口](../reference/reference.md) |

## 仓库怎么改

以下是下一阶段的实施顺序。当前仓库已有资料与环境，`package.json` 仍是占位脚本。

1. **先固定项目和审阅记录。** 根目录新增 `AGENTS.md`，约定从 `projects/<片名>/` 读取进度。每集保存 `script/`（原稿、优化稿、证据）、`storyboard/`（镜号、台词锚点、关键帧和素材引用）、`audio/`（音色引用、干声、分轨、SRT）、`review/`（预演和意见）、`render/`（成片）。`project.json` 记录当前阶段、各版本及作者批准的组合。跨片可复用的资产进 `assets/`，参考原件仍从 `reference/` 引用。
2. **让 Codex 能找到导演和执行者。** 保留现有 `.codex/config.toml` 的项目设置。将导演 skill 的原件放在 `.codex/skills/mercury-director/`，包含 `SKILL.md`、审稿与分镜提示词模板、项目记录样例；从 `.agents/skills/mercury-director` 建相对符号链接到原件，使 Codex 能发现它。`.codex/agents/` 放导演、制作和审片角色的 TOML，写明各自的模型、输入及交付。现有 `.gitignore` 忽略这两个目录，实施时为需共享的原件、角色和发现入口添加精确例外。需要跨仓分发时，再把同一组资源封装成插件。[Codex 技能发现规则](https://developers.openai.com/codex/skills/) · [项目级子 Agent 配置](https://developers.openai.com/codex/subagents/)
3. **接入可执行的制作入口。** 在 `src/` 放共用 Remotion 合成与镜头组件，在 `scripts/` 放配音、对齐、预演和终版导出。给 `package.json` 增加面向单个项目的命令：静音预演读已审文稿；配音读已审分镜和本人样本；带声预演读实录时间轴；终版导出核对终审版本。如果重新生成导致版本变化，把受影响项标回待审。
4. **用一段稿走完整个闭环。** 选有跨镜动作和一个难读专名的段落，依次审稿、看静音预演、听本人音色、审带声预演、导出。再试一次只改读音与一次只换截图，确认能局部重做、能从上次审阅恢复，并且终版始终对应你最后通过的版本。
