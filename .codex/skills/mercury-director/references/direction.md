# 从段落得到连续分镜

## 先选表达，再决定镜头怎么动

1. 写出这一段之前观众已经知道什么，这一段结束时还能多回答什么。选一个能贯穿段落的对象。铺垫留出预期；转折发生在结果偏离预期的那一拍。几句台词可以共同完成一次变化。
2. 把“交给、挡住、返回、发现”改写成能看见的动作。先用少量对象跑清运动关系，再加材质。进入下一镜时说明保留哪个对象、谁已改变状态、视线从哪里接上。
3. 需要看关系时保持全景，需要辨认字段时沿已知对象推近，需要两种状态比较时固定机位。读数、照片里的表情或重要停顿可以停稳。人物和物件退出画面时，交代留下什么线索引向下镜。
4. 事实性网页或日志先给足来源上下文，再突出能证明台词的区域。原始截图保存到本片 `assets/`，另记来源、日期、支持哪句话；高亮、遮罩和裁切保留成可改图层。素材尚缺时用标明“待补”的占位，不能把生成的界面当成实验结果。
5. 交审时在关键帧旁放对应台词，高亮动作触发词。按实际画幅串成带临时字幕的静音预演。挑最难的接点一倍速连看，检查读字、空间方向、工作区归属和揭示先后。仅有静图时，清楚写出哪段动态尚待预演。

## 一个可交接的三镜示例

以下是导演练习。假定已审台词为“请求发了两次。第一次已经写入，只是回执晚了。再来一次，系统怎么知道是同一笔？”本片稿段为 S03–S05，正式秒点待配音。制作时注明本片采用的画幅、可用素材及上一段留给第一镜的对象。

| 镜号与对应台词 | 起始构图 → 触发与运镜 → 结束状态 | 留给下一镜 / 作者能判断什么 |
| --- | --- | --- |
| M04 · S03“发了两次” | 发送端左，接收端右。镜头固定在能看清两端的景别。第一次发送后，左端仍在等回执；说到“两次”时第二封信从同一起点出发。两封信显示同一业务号。 | 保持两封信及方向。观众能区分两次尝试和两笔业务吗？ |
| M05 · S04“已经写入” | 沿第一封信推近右侧记录，只亮起一行。说到“回执晚了”时，视线沿返回线移到半途停住的回执。若稿件在陈述真实实验，此处插入可核对的记录截图，给那一行留出阅读时间。 | 让记录与回执同框，再回全景。观众能指出等待发生在哪一端吗？ |
| M06 · S05“同一笔” | 第二封信即将抵达。切回时保留右侧已有记录，镜头固定，将信上的号与记录中的号排在同一视线上。念到问题就停住，留下比较时间。 | 下一段可直接从这两个号开始。观众是否已预期会重复记账，并想知道如何处理？ |

把上表格式应用到本片时，再给每行附上实际素材路径、是否需要拟音、与上一镜或下一镜的衔接点。布局、动作逻辑和屏幕证据尽量由可重渲代码控制。做有历史状态的模拟可先计算轨迹；跳播同一时刻应得到同一帧。若静音时主线消失，先修动作和空间关系；若关系清楚但节奏拖，删等待或缩短移镜，保留真正需要阅读的停顿。
